# Измерение геометрии подземелий

Экспериментальный серверный инструмент для отдельного одноразового мира. Это не готовый мод генерации.
По умолчанию выключен; перед установкой Harmony проверяет серверный режим и имя мира.
Основной профиль, существующие сохранения и клиент для этой проверки не используются.

## Сборка и условия запуска

Сверенные версии библиотек — в [lock](../../manifests/dungeon-geometry.lock.json).
Проверена игра `l-1.0.20`, серверный Steam build `25909431`; инструмент использует внутренние поля игры.
После обновления игры требуется повторная проверка адаптера.

```sh
DOTNET_ROOT="$PWD/.local/legacy-adaptation/tools/dotnet" \
  .local/legacy-adaptation/tools/dotnet/dotnet build \
  tools/dungeon-geometry-probe/DungeonGeometryProbe.csproj -c Release
```

По умолчанию ссылки на DLL берутся из `.local/server-gameplay`; изменить можно через `-p:GameDir=/path/to/server`.
Сборка не копирует игровые DLL в результат. Устанавливать только собственную `DungeonGeometryProbe.dll`
в `BepInEx/plugins/DungeonGeometryProbe` отдельной копии чистого сервера с библиотеками из lock.
PoV, EpicLoot и моды локаций в геометрическом прогоне не участвовали.

Явный конфиг `BepInEx/config/ubermodpack.dungeon-geometry-probe.cfg`:

```ini
[Probe]
Enabled = true
ExpectedWorld = DungeonGeometry
```

Использовать новый мир `DungeonGeometry`, отдельный `-savedir` и свободный порт по
[runbook](../../docs/runbook.md). Пароль и журналы — только в `.local/`.
До запуска проверить ресурсы и порты; измеренный прогон ограничен 4 ГиБ RAM, 200% CPU и 900 секундами.
После `GEOMETRY_PROBE_COMPLETE` штатно остановить сервер и сохранить результаты.
Не оставлять инструмент на постоянном сервере: включённый плагин повторяет эксперимент при каждом запуске.

## Что делает инструмент

- Перечисляет зарегистрированные `DungeonGenerator` с алгоритмом `Dungeon`.
- Находит первый подходящий включённый prefab штатной локации для каждого генератора.
  Учитывает исходное смещение входа и custom interior; все варианты расположения/поворота не перебирает.
- Для каждого типа сравнивает штатный профиль и `depth-first` на seed 1001–1006, затем повторяет 1001.
- В кандидате повышает `m_minRooms` минимум до 48, `m_maxRooms` минимум до 160.
  Второе поле ограничивает попытки размещения и не гарантирует 160 комнат.
  До порядка размещения 17 предпочитает глубокие стыки, затем ранние развилки.
  После неудачной штатной попытки исключает выбранный стык из дальнейшего выбора.
- Сохраняет штатные подбор комнат, проверки границ/коллизий и закрытие тупиков.
  Патч выбора соединения действует только на текущий экземпляр пробы.
- Вызывает штатную генерацию `Ghost`, фиксируя seed через `GetSeed`, до очистки извлекает граф комнат.
  Отдельно восстанавливает комнаты через штатные `Load/Spawn` и сравнивает граф, глубины и геометрию.
- Запоминает происхождение сетевых объектов в момент размещения комнаты.
  При отсутствии такой записи пробует единственный вмещающий габарит; неразрешённые объекты помечает `unknown`.
  Это ещё не адаптер всех спавнеров и позднее появляющихся существ.

В `BepInEx/config/DungeonGeometryProbe` появляются `inventory.json`, `anchors.json` и `geometry-results.json`.
Это сырые локальные артефакты: не добавлять их, DLL или сохранения в Git.
Публикуются только собственные агрегированные измерения без полных раскладок и инвентаризаций.

## Как понимать измерения

Граф строится по совпадающим стыкам `RoomConnection`: штатный контакт, одинаковый тип, встречное направление.
Внешний вход и разделители исключаются; кратчайший путь считается BFS от единственной входной комнаты.
В глубину, число комнат и развилки не включаются заглушки и разделители.
Развилка — обычная комната с тремя или более соседними обычными комнатами.

Пересечения проверяются по штатным ориентированным габаритам комнат с допуском 0,1 м.
Заглушки, разделители и габариты с нулевым размером не участвуют в этом аудите.
Это не проверка всех треугольников меша, лестниц, дверей, разрушаемых стен и пути персонажа.
Некоторые строительные стыки не соответствуют игровым проходам; требуется проверка конкретного типа.

Поле `structural_pass` объединяет связность, габариты, закрытые стыки и счётчик `m_requiredRooms`.
Оно не является игровой приёмкой и не включает отдельный диагностический счётчик `mismatched_contacts`.
В публичной сводке эти признаки разделены: штатный генератор тоже не гарантирует достижение `m_minRequiredRooms`.
Контакт с другим типом стыка учитывается в обоих направлениях и сам по себе не доказывает разрыв прохода.

`proposed_depth_pass` — исследовательский ориентир глубины ≥16 и минимум двух развилок.
Он не является окончательным требованием всех типов, особенно цельных арен и квестовых интерьеров.
`duration_ms` включает генерацию и наш сбор данных; это не чистое время штатного генератора.
`reload_matches` относится к `Load/Spawn` в том же процессе, не к перезапуску сервера.

Результаты и ограничения — в [отчёте](../../docs/reports/2026-10-28-dungeon-geometry-balance.md).
Чистая часть графа подключена к [проверкам](../dungeon-depth-check/Program.cs) без Unity.

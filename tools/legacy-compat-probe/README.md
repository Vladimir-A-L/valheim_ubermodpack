# Эксперимент совместимости старых модов Therzie

Инструмент создаёт **частично исправленную копию** закреплённой DLL. Это исследовательский кандидат,
не готовая адаптация и не разрешение устанавливать его в основной профиль.
Результаты запуска и оставшиеся ошибки описаны в
[отчёте](../../docs/reports/2026-10-28-legacy-adaptation.md).

Поддерживаются только Fire and Ice 2.0.8, MonstrumDeepNorth 2.0.6 и MonstrumAshlands 1.1.8.
SHA256 оригиналов закреплены в коде и в
[исходном lock](../../manifests/legacy-content-probe-20261028.lock.json).
Патч требует точного совпадения исследованных `assembly_valheim.dll` и `assembly_utils.dll`
с Linux-сервером build `25909431`, версия `l-1.0.20`.

## Что меняет эксперимент

- Fire and Ice: четыре чтения и четыре записи углов heightmap переведены с `Biome[]` на `BiomeSector[]`.
  Для изменяемого угла создаётся отдельный сектор с новой парой `Biome`/`BiomeType`; остальные поля копируются.
  Исходный общий сектор мира не изменяется. Влияние такого переноса на северный рельеф ещё не принято.
- Оба Monstrum: координаты зон и атрибуты Harmony переведены с `Vector2i` на `Vector2s`,
  чтение координат учитывает `Int16`; патч случайной точки вызывает статический `GetZonePos`.
  Он по-прежнему выбирает центр зоны при радиусе локации от 32 м.
- Ashlands: встроенный PieceManager явно выбирает перегрузку `PieceTable.SetCategory(Int32)`.

Проблемные патчи не отключаются для получения формально чистого запуска. Вместе с тем эти изменения
не устраняют все старые обращения к API: остаются несовместимости предметов, эффектов и строительства.

## Сборка и применение

Проверено с .NET SDK `8.0.408`, зависимость `Mono.Cecil 0.11.6` закреплена в проекте.
Исходные DLL брать из сверенных архивов; бинарники игры, моды и результаты хранить только в `.local/`.
Игра и сервер должны быть остановлены. Работать на отдельной поставке и новом мире по
[runbook](../../docs/runbook.md).

```bash
dotnet build tools/legacy-compat-probe -o .local/legacy-patcher
managed="$PWD/.local/server/valheim_server_Data/Managed"
original="$PWD/.local/original-mod/WarfareFireAndIce.dll"
output="$PWD/.local/patched-mod"
dotnet .local/legacy-patcher/LegacyCompatProbe.dll patch "$managed" "$original" "$output"
```

`original` задаёт одну исходную DLL нужного мода. Выходной файл должен отсутствовать;
повторное применение и перезапись оригинала отклоняются. Для следующей попытки выбирать новый каталог.
Программа проверяет SHA256 исходного мода и двух сборок игры, структуру изменяемых инструкций,
а после записи — сохранность всех встроенных ресурсов. Рядом создаётся JSON с временем UTC,
хешами, изменениями и оставшимися неразрешимыми ссылками.

Для статического аудита без изменения DLL:

```bash
dotnet .local/legacy-patcher/LegacyCompatProbe.dll audit "$managed" "$original" .local/legacy-audit
```

Аудит проверяет прямые ссылки на `assembly_valheim`, включая разрешение перенесённых типов.
Он не обнаруживает все ошибки поиска методов по строке, Harmony, Unity-ресурсов и игровой логики.
Даже пустой список ошибок не заменяет запуск и игровую проверку.

Собственный код патчера можно хранить в Git. Извлечённый код сторонних сборок, сами DLL,
их встроенные ресурсы и сырые журналы в репозиторий не включать.

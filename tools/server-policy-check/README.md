# Проверка допуска модов перед передачей стенда

Утилита вызывает `IntegrityPolicyStore` и `IntegrityValidator` из закреплённой ServerManager.dll.
Она проверяет эталоны `required/optional` против списка клиентских GUID и SHA256 без запуска Valheim.
Сборка использует установленные ServerManager, BepInEx и Mono.Cecil; ничего не скачивает.

```bash
.local/legacy-adaptation/tools/dotnet/dotnet build tools/server-policy-check -c Release -p:GameDir=/absolute/path/to/server
.local/legacy-adaptation/tools/dotnet/dotnet tools/server-policy-check/bin/Release/net8.0/ServerPolicyCheck.dll .local/stand/state/ServerManager .local/stand/expected-client.json
```

Оба каталога эталонов должны существовать. Для автономной проверки положить в `required`
закреплённую ServerManager.dll: работающий сервер включает собственную DLL в политику автоматически,
а отдельный `IntegrityPolicyStore` этого не делает.
Остальные эталоны берутся из проверенной поставки, не из произвольного присланного набора модов.

Приватный JSON — массив объектов с полями `guid`, `name`, `sha256` для фактически загружаемых клиентских
плагинов. Обычные библиотеки без `BepInPlugin` отдельными записями не являются.
Манифест установщика частичного обновления не заменяет полный список плагинов клиента.

JSON результата содержит число правил, число записей, решение и коды отказов.
Код выхода 0 означает допуск по этой политике, 1 — отказ, 2 — неверные аргументы.
Ошибка чтения или некорректная политика также завершают проверку неуспешно.
Администраторские исключения не включаются. Отсутствие optional-мода разрешено,
неизвестный плагин, неверный SHA256 и отсутствие required-мода отклоняются.

Утилита не подключает клиента к серверу и не читает политику из памяти работающего процесса.
После изменения эталонов отдельно проверить журнал `Reloaded mod folder policy` и число правил.
Успешный клиентский вход фиксировать только после настоящего подключения.

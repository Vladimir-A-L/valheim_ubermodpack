# Технический прототип глубины и награды

Проверяет назначение модификаторов PoV и отдельную награду EpicLoot в выбранном сундуке.
Это диагностический плагин для одноразового dedicated server, не готовый генератор подземелий.
Автоматического изменения комнат, спавнеров, всех сундуков или действующего клиента нет.

## Границы

- Мост допускает только PoV 5.3.6 с SHA256 из [lock](../../manifests/dungeon-prototype.lock.json).
  Он использует внутренний метод PoV: публичный API не предоставляет назначения модификаторов.
- В `RarityRoll.Sync` заменяется один вызов назначения набора. Только явно помеченные ZDO используют
  сохранённый набор; остальные существа проходят штатную функцию. Захват сетевого владельца не выполняется.
- Генераторы добычи/опыта PoV и EpicLoot не патчатся. Специальная награда добавляется отдельным вызовом,
  один раз в выбранный сундук. Прототип использует `SwordBronze` как проверочный предмет.
- Сила охраны пока передаётся явно. Автоматический граф комнат и привязка реальной охраны не реализованы.
- Начальные веса EpicLoot `[95, 4, 1, 0, 0, 0]` взяты из исследованной базовой таблицы лесного склепа.
  Это собственный профиль специального слота; итоговые таблицы других модов динамически не считываются.
- Редкость выбирается по модели лучшего из `k` вариантов, выдаётся один предмет.
  `k` использует фактические `Reward per modifier` и `LootDifficulty.StarScale`; базовая строка расчёта
  соответствует противнику без звёзд и бонусов количества игрока. Это калибровка, не копия всей экономики PoV.
- Когда расчётная вероятность Rare в справочном распределении PoV достигает `RareFloorReferenceChance`,
  низкая редкость специального предмета повышается до EpicLoot Rare. Шансы Epic и выше этим минимумом не меняются.
  Default 0,5 даёт первую такую ступень при 8 модификаторах на исследованных стандартных настройках.
- Выданная награда, исходное число модификаторов охраны, seed и редкость фиксируются в ZDO сундука.
  Повторный вызов не выдаёт предмет повторно. Штатное содержимое сундука не удаляется.

## Сборка и проверки без игры

Нужен .NET SDK 8.0.408 и локальная проверенная поставка Valheim `l-1.0.20` с BepInEx 5.4.2351.
Сторонние DLL не входят в репозиторий и не копируются в результат сборки.
В `GameDir` ожидаются `valheim_server_Data/Managed` и библиотеки `BepInEx` закреплённой поставки.

```bash
dotnet build tools/dungeon-depth-prototype/DungeonDepthPrototype.csproj -c Release -o .local/dungeon-prototype/build -p:GameDir="$PWD/.local/server-gameplay"
dotnet run --project tools/dungeon-depth-check/DungeonDepthCheck.csproj -c Release
```

Если SDK установлен приватно, использовать его `dotnet` с соответствующим `DOTNET_ROOT`.
Математические проверки не требуют Unity и не запускают игру.

## Изолированный запуск

Собрать новый каталог сервера по [runbook](../../docs/runbook.md), используя точные версии из lock.
Сначала проверить один PoV с библиотеками, штатно остановить сервер и сохранить его журналы.
Затем добавить EpicLoot 0.15.3 с согласованным конфигом и `DungeonDepthPrototype.dll` в отдельный каталог plugins.
Основной профиль не заменять. Мир и каталог состояния для технического прогона должны быть отдельными.
Перед запуском проверить RAM/диск/порты и задать лимиты процесса.

Прототип выключен по умолчанию. В тестовом `BepInEx/config/ubermodpack.dungeon-depth-prototype.cfg`:

```ini
[Probe]
Enabled = true
ExpectedWorld = DungeonPrototype

[Reward]
RareFloorReferenceChance = 0.5
```

Использовать `scripts/start-dev.sh` с отдельными `VALHEIM_SERVER_DIR`, `VALHEIM_STATE_DIR`,
`VALHEIM_PASSWORD_FILE`, `VALHEIM_WORLD_NAME=DungeonPrototype`, свободным портом и уникальным unit.
Для выполненного прогона применены 4 ГиБ RAM, 200% CPU и лимит времени 600 секунд.
Плагин проверяет имя мира и серверный режим до установки патча и создания объектов.

В мире временно создаются скелеты/грейдворфы и сундук; после проверок объекты удаляются.
Результат — `BepInEx/config/DungeonDepthPrototype/probe-result.json` и маркер `DUNGEON_PROBE_PASS`
либо `DUNGEON_PROBE_FAIL`. Файл результата может остаться от предыдущего запуска:
сверять время UTC и маркер в журнале именно текущего процесса.
После получения результата штатно остановить сервер и проверить сохранение.

Выполняются синхронизация PoV, перемещение, изменение звёзд, сериализация/десериализация ZDO,
контроль непомеченного существа, 600 000 выборов редкости, вызовы API EpicLoot и повторная выдача в сундук.
Сериализация ZDO не заменяет перезапуск мира с сохранёнными существами, смену владельца между клиентами
или визуальную игровую приёмку. Баланс боя, производительность глубокого данжа и остальная сборка ещё требуют испытаний.

Результаты и расчёт шкалы — в [отчёте](../../docs/reports/2026-10-28-dungeon-prototype.md).

# Постоянный тестовый стенд

Windows-компьютер целиком предназначен для испытаний. Используется существующая учётная запись:
её стандартное хранилище Valheim содержит только тестовые сохранения. Новую учётную запись не создавать.

## Клиент

| Назначение | Расположение |
| --- | --- |
| Рабочий профиль | `%LOCALAPPDATA%\ValheimTest\current` |
| Клиент с модами | `current\client` |
| Сохранения | `%USERPROFILE%\AppData\LocalLow\IronGate\Valheim` |
| Персонажи | `characters_local` внутри хранилища сохранений |
| Клиентские backup | `current\backups` |
| Журнал клиента | `current\client.log`, одна предыдущая версия `.previous` |
| Исходные настройки | `current\settings-backup` |

Чистая установка Steam остаётся источником для сравнения. Рабочий клиент находится вне каталога Steam,
чтобы обновление чистой установки не подменило проверяемую поставку. Новые копии клиента на каждый прогон
не создавать. При изменении состава подготовить одного нового кандидата и сохранить прежнюю поставку до приёмки.

Запускать Steam, затем ярлык рабочего стола `Valheim Test`. Он вызывает
[start-client-test.ps1](../scripts/windows/start-client-test.ps1): проверяет отсутствие второго клиента,
свободные RAM/диск, создаёт компактный backup, запускает игру и после штатного выхода повторяет backup.
Параметр `-NoWait` предназначен для контроллера автоматизации: после выхода он должен отдельно вызвать
[backup-client-test.ps1](../scripts/windows/backup-client-test.ps1).

Настройки экрана сохраняются. При запуске ничего не скачивается, кэши не очищаются.
`-savedir` клиенту не передавать: в установленной сборке его обработчик вызывается сервером, а не обычным клиентом.
Персонажи постоянно живут в `characters_local`; не переносить их в `current\state` после каждого теста.
Steam Cloud выключен для Valheim. В выборе персонажа должны быть `Local save` и сообщение об отключённом Cloud.
Глобальная настройка Cloud остальных игр не меняется.

## Новые испытания данжа и сброс комплекта

Исключение для [пробы мини-босса от 30 октября](reports/2026-10-30-dungeon-miniboss-plan.md):
последним уточнением пользователь разрешил восстановить исходные расходники и комплект Drug,
заменить бронзовый меч медным ножом качества 3 и сбросить распределение PoV с возвратом заработанных очков.
Боевой и ремесленный опыт, уровни и обычные навыки сохраняются. Исходный серверный профиль и внешние данные
сохранять отдельно; возврат очков проверять до и после штатных `ResetTreeFree` и `CraftProgress.Respec`.
Для шести склепов нужны разные случайные наборы из десяти свойств и фиксированная награда глубины 64.

29 октября пользователь разрешил для проверки построения и проходимости каждый раз создавать новый данж,
возвращать снаряжение выбранного тестового персонажа в исходное состояние и очищать инвентарь.
Повторное разрешение на эту подготовку не требуется. Во время пользовательского сеанса её не запускать.

Для каждой новой итерации:

1. После остановки клиента и сервера сохранить согласованный checkpoint мира, серверного персонажа
   и внешних данных модов. Записать версии, seed и идентификатор испытания в приватный журнал.
2. Создать новый тестовый данж. Существующий посещённый данж не переделывать установкой дверей поверх
   уже переместившейся охраны. Для сравнения вариантов можно повторно использовать один seed на чистых копиях.
3. Назначить отдельный `PreparationId`, включить `AutoPrepareOnce` и `ResetInventory` только для выбранных
   мира и персонажа. После подтверждения прибытия очистить прежние вещи и выдать согласованный комплект:
   текущее качество экипировки 3, полная прочность, исходный запас еды и расходников, восстановленное здоровье.
   Использовать сохранённую спецификацию комплекта, а не встроенный запасной набор качества 2.
4. Проверить предметы, экипировку и отметку завершения подготовки, сохранить персонажа.
   При повторном входе в ту же итерацию вещи, добыча, состояние дверей и данжа не сбрасываются.
   Новый `PreparationId` означает новое испытание, а не очередное подключение.

Общее разрешение касается инвентаря и комплекта; дерево PoV сохраняется, кроме явно указанного выше опыта.
Для проверки геометрии допустимы god и бесконечная выносливость, ghost выключен; это не проверка боевой победы.
У обычного боевого опыта и серии с условными смертями режимы фиксируются отдельно.
После неудачного прибытия или неполной подготовки сначала проверить состояние; не запускать повторный сброс вслепую.

## Компактные резервные копии

Клиентский скрипт работает только при закрытой игре. Архив содержит сохранения, конфиги BepInEx, настройки
реестра, build manifest и SHA256 DLL плагинов. Игровые бинарники, модовые архивы, кэш и журналы туда не входят.
Каждый файл нового архива проверяется по SHA256. При совпадении содержимого с последним проверенным архивом
новая копия не создаётся. Максимум пять архивов, включая защищённые файлом `<имя>.zip.keep` точки восстановления.
Если все пять защищены, новый backup требует пересмотра защиты; скрипт не удаляет их автоматически.

Установщик ручного патча использует отдельную папку `ForestCryptQA-private-backups` внутри выбранной игры.
В её корне остаются новая копия и до четырёх прежних, включая защищённые `.keep`.
После проверки новой копии остальные переносятся в подпапку `archive`, с проверкой SHA256 и без удаления.
При совпадении имени сохраняются оба архива; пять защищённых копий требуют снять один маркер `.keep`.
Это правило установщика, отдельное от ротации `backup-client-test.ps1` и серверных checkpoint.

Для модов с данными вне стандартного хранилища и `BepInEx\config` добавить абсолютные пути в приватный
`current\backup-extra.json` — JSON-массив строк. Запуск передаёт их в backup как `extra-0`, `extra-1` и далее.
В текущем составе дополнительные каталоги не настроены. Состав сохраняемых данных проверять при добавлении модов.

Серверное состояние хранится в `.local/state-gameplay`, рабочая поставка — в `.local/server-gameplay`.
Параметры запуска находятся в приватном `.local/stand.env`:

```bash
source .local/stand.env
bash scripts/start-dev.sh
systemctl --user stop valheim-gameplay
```

Останавливать клиент и сервер перед согласованным checkpoint. Клиентский ZIP, весь каталог серверного состояния,
конфиги и внешние данные серверных модов связывать одной записью checkpoint. Серверные архивы пока ротируются
оператором: максимум пять в `.local/backups`; последнюю проверенную точку и копию перед изменением учитывать
в этом лимите. Игровые автокопии ограничены четырьмя. Это отдельный механизм, ручные архивы он не удаляет.

Старые полные архивы могут быть заменены компактными только после проверки каждого файла:
данные сохраняются в checkpoint, неизменившиеся бинарники сверяются с оставленной поставкой.
Manifest компактного checkpoint указывает SHA256 manifest поставки. Оба нужны для восстановления.
Не удалять соответствующую поставку, пока от неё зависит сохранённый checkpoint.

После обновления 28 октября предыдущий клиент находится в `ValheimTest\previous-20261028`,
предыдущий сервер — в `.local/releases/core-before-20261028/server`.
Checkpoint до обновления — `.local/backups/stand-20261028-checkpoint.tar.gz`,
после обновления — `.local/backups/core-update-20261028-checkpoint.tar.gz`.
Связь с клиентскими архивами и manifest поставки записана в `.local/update-20261028/final-checkpoint.json`.
При откате возвращать согласованный набор бинарников, состояния, конфигов и внешних данных модов.
Предварительная приёмка нового набора не выставлена из-за предупреждений; детали — в
[отчёте обновления](reports/2026-10-28-mod-update.md).

Восстановление выполнять в пустой временный каталог. Из компактного серверного checkpoint взять состояние
и изменяемые файлы, бинарники — из указанной поставки. Сверить все SHA256, затем проверить загрузку мира.
Для клиента распаковать ZIP, сверить `manifest.json`, при закрытой игре вернуть `saves` в стандартное хранилище,
`config` — в рабочий BepInEx. `extra-*` вернуть в соответствующие исходные каталоги.
Настройки реестра восстанавливать только когда это нужно для отката. Временную распаковку удалить после проверки.

## Проверки инструментов

```bash
make check
```

На Windows с закрытой игрой дополнительно выполнить:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/test-client-backups.ps1 `
  -BackupScript scripts/windows/backup-client-test.ps1
```

Проверка использует временные тестовые файлы: одинаковое содержимое не дублируется, ротация оставляет пять
архивов и защищённую точку, восстановление совпадает по хешам, повреждённый архив отклоняется.
Результаты организации и игровой проверки хранятся отдельно в отчётах, сырые данные — вне Git.

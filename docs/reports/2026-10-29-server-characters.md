# Серверные персонажи и счётчик условных смертей

Пользователь подтвердил клиент ForestCryptQA 0.3.0 на своём компьютере и новый тестовый профиль Drug.
Обновление 0.3.1 он не устанавливал. Подготовлено прямое обновление до 0.4.0 с ServerManager 1.2.5.
[Закреплённая поставка](../../manifests/server-characters-20261029.lock.json),
[порядок эксплуатации](../server-characters.md). Геометрия лесного склепа и правила наград не изменялись.

## Выбор и ограничения

ServerManager поддерживает установленную Valheim 1.0.20, серверные native `.fch`, резервирование,
проверку состава модов и административное восстановление. ServerCharacters 1.4.16 и AzuAntiCheat 4.3.11
на момент проверки помечены устаревшими; устанавливать их одновременно с выбранным решением не требуется.
[ServerManager](https://thunderstore.io/c/valheim/p/sighsorry/ServerManager/),
[ServerCharacters](https://thunderstore.io/c/valheim/p/Smoothbrain/ServerCharacters/),
[AzuAntiCheat](https://thunderstore.io/c/valheim/p/Azumatt/AzuAntiCheat/).
Античит остаётся отдельным поздним этапом. Встроенные действия ServerManager переведены в `log`,
пределы характеристик подняты для QA. Проверка DLL и часть ограничений команд остаются действующими.

Серверный профиль имеет приоритет при входе, но локальные файлы клиента не исчезают.
Редактирование серверного файла при подключённом игроке может быть перезаписано состоянием в памяти;
для планового изменения нужны выход игрока, checkpoint и остановка сервера.

## Выполненные проверки

ServerManager сначала отдельно запущен на новом мире с BepInEx, затем включён в копию ForestCryptQA
с PoV, EpicLoot и собственным модулем. Отдельный сервер ограничен 150% CPU и 3 ГиБ RAM.
Основной тестовый сервер продолжал работать на прежней поставке во время подготовки кандидата.
Ошибок инициализации ServerManager и модуля счётчика не обнаружено. Штатные предупреждения headless Unity
о видео/шейдерах сохраняются: запуск не выдаётся за сборку без предупреждений.

Создан отдельный StorageQA на Windows-стенде. Проверен импорт локального профиля, появление native `.fch`,
завершение checkpoint персонажа и автоматическое закрепление серверной копии с подтверждённым reload настроек.
Первый запуск обнаружил ошибку таймера: вступительный полёт занимал больше 90 секунд.
Таймер подготовки теперь запускается после вступления. После исправления повторный вход выполнил
телепортацию и первую выдачу бронзового комплекта; наблюдались god=true, ghost=false и 18 помеченных стеков.

Две игровые контрольные пробы применили настоящий урон: 10 → 1, повторный удар при 1, снова 10 → 1.
Каждая дала ровно две условные смерти в отдельном серверном счётчике. Повторная отправка уже принятого
события не увеличила итог. После рестарта сохранённые две смерти восстановлены; следующая проба дала итог четыре.
В обычном бою со скелетами сервер также зарегистрировал четыре условные смерти StorageQA до завершения сессии.
Подтверждённое начало обычной попытки показано в HUD. События стенда не относятся к Drug.

Журнал хранит измерения, а вычисление перехода и итог выполняет сервер. Привязка идёт к реальному RPC
аутентифицированного соединения, а не к переданному клиентом ID отправителя. Сервер подтверждает событие
после записи на диск; очередь клиента переживает перезапуск, повторы распознаются по идентификатору и SHA256.
Измерения HP остаются клиентскими, поэтому это механизм испытаний, не доказательство отсутствия читов.

Чистые .NET-проверки: 11 527 утверждений, включая повтор/конфликт сообщения, порядок, независимость аккаунтов,
восстановление журнала, отказ записи и отделение контрольных проб. `make check`: 35 тестов,
compileall, shellcheck и diff check. Установщик проверен настоящим Windows PowerShell:
установка четырёх файлов, SHA256, неизменность сохранения, восстановление backup и отказ неизвестной версии.

Дополнительно восстановлен согласованный серверный backup: SHA256 совпал у всех 258 файлов.
Старая локальная копия StorageQA без комплекта заменена серверным профилем при входе:
все 22 стека совпали, повторной выдачи нет, обычный счётчик восстановлен до четырёх.
Журнал до checkpoint сохранился целиком. Повторный вход в восстановленный мир подтверждён двумя кадрами HUD.
Проверена финальная DLL из клиентского архива, её SHA256 совпал на обеих сторонах.

## Статус поставки

Клиентский архив 0.4.0 готов для установки поверх 0.3.0; промежуточный патч не нужен.
Установщик требует закрыть Valheim, создаёт и проверяет резервную копию; выход из Steam не требуется.
Предыдущая серверная поставка сохранена, backup перед заменой сверён по 426 файлам,
старейшая из шести копий этого набора удалена по правилу ротации. Последний проверенный checkpoint сохранён.
На прежнем тестовом сервере загружены существующий мир, ServerManager и модуль счётчика.
Все 11 DLL обновлённого исходного клиентского overlay совпали с серверными эталонами по имени и SHA256.
Лимиты основного тестового сервера — 200% CPU / 4 ГиБ RAM; это не оценка игровой вместимости.

До первого переноса допуск ограничен известным аккаунтом Drug. Одноразовый процесс ждёт его native `.fch`
и завершённого checkpoint, после чего закрепит серверный приоритет. Это ожидающее действие,
не подтверждение состоявшегося переноса. Установка на компьютере пользователя, первый перенос Drug
и его оценка сложности ещё не подтверждены. Начинать проход следует после сообщения «Тест готов» в игре.
Вспомогательные клиент и сервер остановлены штатно; финальный согласованный checkpoint сохранён и сверён.
Сырьё проверок, архивы, native профили и идентификаторы остаются в `.local/`.

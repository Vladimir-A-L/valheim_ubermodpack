# Постоянный профиль тестового клиента

Дата: 28 октября 2026 года, Asia/Yekaterinburg. Машинные наблюдения сохраняются с временем UTC.
Пользователь разрешил оставить настройки клиента после теста и ограничить количество резервных копий.

## Применённые настройки

- Отдельная копия клиента 1.0.20, Steam build `25909357`, прежний закреплённый состав модов.
- Экран стенда 1920×1080, 60 Гц, RTX 4060; перед работой свободно около 27 ГиБ RAM и 541 ГиБ диска.
- Для существующих OCR-сценариев оставлено окно 1280×720, DPI 96, масштаб UI 100%, язык English.
  Отрисовка Native, лимит 60 FPS, VSync выключен, уменьшение фоновой нагрузки включено.
- Custom на основе Medium: детализация High, растительность, свет и тени Medium, SSAO Low,
  15 активных источников света, одна точечная тень, дальность Classic 288 м, качество ткани 2.
  Bloom, глубина резкости, размытие движения и хроматические аберрации выключены.
- Включён штатный `Skip intro cinematic`; отключён `Show Splash on Startup` AdventureBackpacks.
- Кэш метаданных BepInEx уже был включён и сохранён. Консольное окно остаётся выключенным.
  Отключена дублирующая запись Unity-журнала в `LogOutput.log`; собственный Unity-журнал и журнал модов остаются.
- Для FPS доступна штатная панель F2 в игровом мире. Дополнительный мод не установлен.
  Наличие счётчика сверено с реализацией установленной версии; измерение FPS в мире в этот прогон не входило.

Параметры закреплены в [профиле](../../configs/client-test.json), применение — в
[PowerShell-скрипте](../../scripts/windows/set-client-test-settings.ps1).
Настройки Unity общие для учётной записи Windows; это разрешённое пользователем постоянное изменение.
Скрипт отказывается работать при запущенной игре и хранит одну исходную копию настроек вне Git.

- Исходный запуск показал вступительный ролик и повторное окно AdventureBackpacks.
  После отключения выполнены повторные запуски; получено главное меню без этих состояний,
  в новом журнале отсутствует запуск `$cinematics_intro`.
- После применения профиля сверены все 27 значений реестра. На свежих кадрах интерфейса подтверждены
  пропуск ролика, снижение фоновой нагрузки, четыре автокопии, разрешение, лимит и графические параметры.
- Загрузчик: `13 loaded, 0 skipped, 0 failed`. В проверенном журнале BepInEx нет записей Error/Fatal.
  Это не означает отсутствия всех Unity-предупреждений или прохождения игровых сценариев.
- При отсутствии окна и foreground захват корректно отказал; игровые действия не продолжались по этим кадрам.
  Окно повторно активировано, получены новые наблюдения, затем продолжена настройка.
- Клиент штатно закрыт, оставшихся заданий `ValheimVision-*` нет. После выхода все 27 значений сохранились;
  оба файла тестового персонажа совпадают по SHA256 с ранее сохранённой копией.
- `make check`: 20 тестов, compileall, shellcheck и проверка whitespace прошли.

Измерение ускорения загрузки в процентах не проводилось: исходный запуск включал ролик и задержку фокуса,
а повторные запуски используют прогретые кэши. Сравнивать эти времена как чистый эффект оптимизации нельзя.
В мир не входили, тестового персонажа не переносили. Известная проблема с фактическим каталогом персонажа
при `-savedir` остаётся: перед игровыми сценариями требуется подтвердить изоляцию хранилища по runbook.

## Резервные копии

Клиент и сервер ограничивают игровые автокопии четырьмя. Для полных согласованных копий принят предел пять,
включая последнюю проверенную восстановлением и копию перед изменением. С одной служебной версией `.old`
это бюджет до десяти точек восстановления. Файлы частей мира не считаются отдельными копиями.
Ручные/миграционные backup и распакованные каталоги восстановления проверяются отдельно.

В локальном каталоге архивов сейчас три архива, около 4,5 ГиБ. Удаление не требовалось.
Два больших архива включают поставку; следующие копии состояния должны ссылаться на отдельную поставку,
а не повторять её бинарники. Ротация полных копий пока ручная; автоматическое удаление не установлено.

Порядок применения профиля и хранения backup обновлён в [runbook](../runbook.md).
Кадры, журналы, исходные настройки и служебные сведения остаются в `.local/` и приватном каталоге клиента.

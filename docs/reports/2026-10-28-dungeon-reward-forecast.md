# Единая шкала наград подземелий и проверка технологии EpicLoot

Дата: 28 октября 2026 года. Статус: исправленный расчётный прогноз и статическая проверка закреплённых данных.
Новые игровые веса, выдача групп и фильтр технологии наших наград ещё не реализованы.
По последнему уточнению пользователя штатная случайная добыча EpicLoot сохраняется дополнительно.
Серверы, клиент, миры и игровые настройки этой проверкой не изменялись.

## Исправление модели

По уточнению пользователя стоимость каждого модификатора и шкала редкости одинаковы для всех подземелий.
Предыдущий прогноз с умножаемыми базами 20/35/60 не соответствовал этому принципу и заменён.
Технология основы предмета, редкость зачарования и число предметов учитываются раздельно.

```text
S = sum(globalModifierCost[id] for id in savedGuardModifiers)
B = locationBonus + S * synergyFactor
protectedProgressionZone -> B = 0
```

`S` — сумма глобальных весов фактически назначенных модификаторов исходной охраны.
Правило синергии также глобальное; без особого сочетания `synergyFactor = 1`.
Замеры DPS/живучести помогают назначить веса и бонусы сочетаний; уже учтённый эффект
не оплачивается второй раз через полный множитель относительной силы.

Надбавка по умолчанию — 0. Варианты пользователя — 20 для Туманных земель и 40 для Глубокого Севера.
Под «ледяными» имелся в виду именно Глубокий Север, не горные пещеры.
Надбавки прибавляются после расчёта очков модификаторов и не меняют их стоимость.

Для гарантированной начальной части предложено обнулять и надбавку: там нет нашей бюджетной добавки,
но сохраняются обычное содержимое сундуков и независимый штатный дроп EpicLoot.
Охрана остаётся без добавленных модификаторов. Без этого исключения при нуле модификаторов
надбавки 20/40 уже дали бы Magic/Rare по примеру ниже. Калькулятор показывает оба случая явно.

Пользователь согласовал: в первом варианте бюджет привязывается к одному сохранённому профилю охранника сундука.
Враг не обязан оставаться рядом или быть убитым: выманивание и обход разрешены.
Максимально возможный, но фактически не назначенный набор не даёт очков.
Суммирование всех соседей, повторных спавнов и дочерних существ не включается автоматически.
Иначе три врага с десятью модификаторами уже дают 300 очков при весе 10, вопреки ожидаемой редкости такой награды.
Для групп охраны нужны отдельные проверенные шаблоны; один источник бюджета не дублировать по всем сундукам.

## Допущения для численного примера

Принят пример пользователя: 10 очков за модификатор до бонусов, 100 очков до полного Ancient.
Это не окончательные веса конкретных модификаторов PoV. Их ещё нужно назначить по расчётам и замерам.
Целевой предел глубокой охраны остаётся равным десяти модификаторам.

Предложенная шкала одинакова для всех групп и всех подземелий:

| Очки внутри одной шкалы | Качество |
| ---: | --- |
| 10 | Обычный предмет без магических данных; метка модели `Common` |
| 20 | Magic |
| 40 | Rare |
| 60 | Epic |
| 80 | Legendary |
| 90 | Mythic |
| 100 | Ancient, полная шкала |

Между узлами — линейные вероятности двух соседних качеств, один выбор на всю незавершённую группу.
Например, при 30 очках шансы Magic/Rare равны; при 95 — Mythic/Ancient.
Mythic присутствует в EpicLoot 0.15.3 и учтён в этом прогнозе.
`Common` обозначает обычный предмет, а не дополнительное магическое значение перечисления EpicLoot.
Пороги и интерполяция предложены для расчёта, не извлечены из штатных таблиц вероятностей мода.

## Одинаковые модификаторы в разных подземельях

Без синергии, при условных десяти очках за каждый модификатор:

| Модификаторы | Надбавка 0 | Туманные земли, вариант +20 | Глубокий Север, вариант +40 |
| ---: | --- | --- | --- |
| 6 | 60: 1 Epic | 80: 1 Legendary | 100: 1 Ancient |
| 8 | 80: 1 Legendary | 100: 1 Ancient | 120: 1 Ancient + 2 Magic |
| 10 | 100: 1 Ancient | 120: 1 Ancient + 2 Magic | 140: 1 Ancient + 2 Rare |

Обычный лут и независимая штатная добыча EpicLoot остаются дополнительно; таблица считает только нашу добавку.
Технологический состав вещей различается
по допустимым таблицам и прогрессии; стоимость получения их редкости остаётся общей.
Без региональных надбавок один и тот же набор модификаторов даёт одинаковый бюджет во всех биомах.
Первый гарантированный Ancient в примере появляется на 10/8/6 модификаторах соответственно.
Случайный Ancient возможен до полной шкалы, но не открывает следующую группу раньше достижения 100.

## Три последовательных превышения Ancient

Каждая полная шкала сохраняет свою группу Ancient, остаток повышает качество следующей группы:

| Бюджет | Дополнительная выдача | Число предметов |
| ---: | --- | ---: |
| 0 | Нет | 0 |
| 5 | 50 монет | 0 |
| 10 | 1 обычный предмет | 1 |
| 100 | 1 Ancient | 1 |
| 160 | 1 Ancient + 2 Epic | 3 |
| 200 | 3 Ancient | 3 |
| 260 | 3 Ancient + 3 Epic | 6 |
| 300 | 6 Ancient | 6 |
| 305 | 6 Ancient + 50 монет | 6 |
| 310 | 6 Ancient + 4 обычных предмета | 10 |
| 360 | 6 Ancient + 4 Epic | 10 |
| 400 | 10 Ancient | 10 |

Формулы: `n = floor(B / 100)`, `r = B - 100 * n`, завершённые Ancient: `n * (n + 1) / 2`.
При `r >= 10` появляется группа из `n + 1` предметов общего качества по остатку.
При `0 < r < 10` вместо неё выдаются 50 монет однократно на сундук. При `r = 0` добавления нет.
Группа состоит из разных вещей одной редкости; бюджет на размер группы не делится.
Количество специальных вещей и 50 монет не умножаются на ресурсы ×3 или число игроков.
Предметы, случайный результат и факт выдачи сохраняются без повторного накопления при открытиях.

Шесть гарантированных Ancient и активная четвёртая группа требуют `310 <= B < 400`.
Это возможный пример работы шкалы, не обязательная цель и не требование к какому-либо данжу.
Не поднимать веса или сложность ради достижения такого количества наград.
При десяти модификаторах по десять очков получаются следующие условия:

| Надбавка | Минимальный коэффициент синергии | Верхняя граница до завершения четвёртой шкалы |
| ---: | ---: | ---: |
| 0 | 3,1 | меньше 4,0 |
| 20 | 2,9 | меньше 3,8 |
| 40 | 2,7 | меньше 3,6 |

Без коэффициента эта ситуация в примере недостижима ни в одном данже.
При коэффициенте 2 максимальные бюджеты — 200/220/240: до четвёртой группы всё ещё далеко.
При коэффициенте 3 — 300/320/340: в обычном профиле только 6 Ancient, в вариантах поздних биомов
уже `6 Ancient + 4 Magic` и `6 Ancient + 4 Rare`.
Это проверка чувствительности, не утверждение о существовании таких сочетаний или их частоте в PoV.
Слова «крайне сложно получить» можно подтвердить лишь после назначения реальных весов и правил сочетаний.

## Технология EpicLoot: не всегда биом минус один

В сохранённом конфиге выбраны `Balance Template = balanced` и
`Item Drop Limits = BossKillUnlocksCurrentBiomeItems`:
[публичная конфигурация](../../configs/core/BepInEx/config/randyknapp.mods.epicloot.cfg).
В этом режиме проверяются глобальные ключи победы над боссами мира, не только личное открытие рецепта.
Исходная таблица добычи определяет кандидатов; ограничитель разрешает их либо подбирает доступную замену.

Статически сверены сгенерированные `iteminfo.json`, `loottables.json`, `biomedata.json` основного
и изолированного профилей, код закреплённой DLL EpicLoot 0.15.3 и официальный исходный код.
Модовые добавления в профилях различаются; приведённые ниже записи штатного снаряжения совпадают.
Сырые конфиги и декомпиляция хранятся вне публичной документации в `.local/`.

- Бронзовая кирка и бронзовые элементы брони разрешаются ключом Древнего `defeated_gdking`.
  Железные варианты — ключом Массы Костей `defeated_bonemass`.
- После Древнего до Массы Костей бронза в затонувшем склепе соответствует текущим ограничениям.
  После Массы Костей железо разрешается там, где попадает в исходный пул; бронза при этом не исчезает.
- У `TreasureChest_sunkencrypt` есть `Tier2Everything` с весом 3 и `Tier3Everything` с весом 1,
  а также отдельная строка осколка. Это веса выбора, не гарантия бронзы или фиксированный шанс железа.
- Обычный `Draugr` использует `Tier3Mob`, где при нуле звёзд исходно выбирается `Tier2Everything`;
  `WeightPerStar` смещает состав к следующей ступени. `Draugr_Elite` использует другую таблицу — `Tier4Mob`.
  Свойства сундука нельзя выводить только из дропа ближайшего обычного драугра.

Точный состав зависит от источника, звёзд для существ, таблиц, мировых ключей и модовых добавлений.
Это не универсальное правило «только технология −1». Бронзовый предмет Ancient допустим, если бронза
разрешена исходным пулом и прогрессией: магическая редкость и металл основы — разные параметры.
Собственный генератор должен выбирать базу по таблицам соответствующего источника EpicLoot с
`BossKillUnlocksCurrentBiomeItems`. Дополнительный постоянный запрет по биому поверх этих правил не нужен.
Прямое зачарование произвольного prefab не доказывает, что этот фильтр был применён.

Первоисточники:

- [Официальное описание таблиц EpicLoot и WeightPerStar](https://github.com/RandyKnapp/ValheimMods/blob/main/EpicLoot/docs/LootTables.md).
- [Проверка ключей боссов и выбор разрешённой основы](https://github.com/RandyKnapp/ValheimMods/blob/13e64c369d7ab230bed0f7033e7ffd7acc75bc43/EpicLoot/src/GatedItemType/GatedItemTypeHelper.cs).

Это проверка правил и данных, не наблюдение серий выпадения в игре и не проверка ключей текущего сохранения.

## Штатная добыча EpicLoot и наша гарантированная добавка

EpicLoot патчит `Container.AddDefaultItems`, регистрирует отложенную выдачу и обрабатывает её при доступе
к инвентарю/сундуку. Поэтому `B = 0` в нашем моде отключает только нашу добавку;
сам по себе он не исключает магические вещи из обычного сундука.
[Официальный патч контейнеров](https://github.com/RandyKnapp/ValheimMods/blob/13e64c369d7ab230bed0f7033e7ffd7acc75bc43/EpicLoot/src/GamePatches/Container_Patch.cs).

Пользователь уточнил, что штатная выдача EpicLoot не мешает. Предыдущее предложение подавлять её отменено.
Итог сундука: обычное содержимое данжа + штатная случайная добыча EpicLoot + наша бюджетная награда.
При нулевом бюджете отсутствует только последний источник; случайная магическая вещь в начальной части допустима.
Наша открытая бюджетом группа гарантирована: случайны допустимые основы, свойства и общая редкость,
но не сам факт выдачи. Штатный шанс пустой добычи и множитель 0,7 не должны отменять нашу группу.
Это правило согласовано пользователем. Наш бонус не зависит от наличия, количества и качества чужой добычи:
её не вычитать из бюджета и не компенсировать её отсутствие увеличением нашей награды.
Для нуля и малого остатка сохраняются правила отсутствия добавки и компенсации 50 монетами.
При создании нашей добавки не вызывать повторно весь штатный генератор содержимого сундука.

Согласовано: бюджет сохранить при назначении охраны, а ключи боссов проверить при первом формировании награды.
Затем сохранить предметы и отметку выдачи; повторное открытие или новый босс не пересоздают готовый набор.
Нужны проверки сосуществования с отложенным броском EpicLoot, сохранения обычных предметов,
передачи сетевого владельца и повторной загрузки. Штатная добыча с противников и награды PoV не меняются.

Даже при правильном металле ранние Ancient могут ускорять зачарование через разборку.
Проверять эту экономику вместе с числом сундуков, глубиной, MWL ×2, ресурсами ×3 и выдачами PoV.
Подсчёт общего результата не создаёт зависимости между источниками: автоматической корректировки нашего
бонуса по чужому дропу нет. Для проверки независимости использовать одинаковые профиль, ключи и seed бонуса
при разных результатах штатной добычи; её броски не должны менять состояние нашего генератора.
Веса едины, поэтому корректировать их нужно глобально, а не скрытой наценкой одного биома.

## Воспроизведение и границы проверки

```sh
python3 scripts/forecast-dungeon-rewards.py --output .local/dungeon-reward-forecast.json
```

[Входные допущения](../../manifests/dungeon-reward-forecast-inputs.json),
[машинный результат](../../manifests/dungeon-reward-forecast-20261028.json),
[калькулятор](../../scripts/forecast-dungeon-rewards.py).
Результат содержит время UTC и SHA256 входного файла, 54 сценария, границы групп,
примеры нулевой охраны с надбавкой и отдельное обнуление гарантированной части.

Проверены арифметика групп и синергии, пороги Ancient, компенсация только положительного малого остатка,
нормализация вероятностей и равенство весов между профилями. Проверки репозитория: `make check`.
Калькулятор считает только нашу бюджетную добавку; штатные предметы EpicLoot и фильтр технологии не моделируются.
Проверки не подтверждают игровой баланс, доступность 40 переходов, выдачу Ancient/групп плагином
или совместную выдачу со штатным EpicLoot. Следующие задачи — реальные веса и адаптер наград сундуков;
геометрические требования и отдельная игровая приёмка сохраняются в [плане генерации](../dungeon-generation.md).

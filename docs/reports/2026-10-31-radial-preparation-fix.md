# Исправление подготовки RadialQa на стенде R3/R4

31 октября 2026 года, Asia/Yekaterinburg. Пользователь подтвердил подключение после исправления
политики модов, но персонаж появился на обычном старте без бронзового комплекта.
Сверка активного соединения показала точное имя `RadialQa`; меню отображает его заглавными буквами.
В r3 клиент ожидал `RadialQA`, поэтому модуль подготовки и запрос серверного журнала не запускались.
Дополнительно в серверном `forest-manual-server.json` остался допуск только для Drug.
Первоначальная передача не проверила согласованность этих настроек.

## Исправление

Выпущен [ForestCryptQA-RadialQa-0.15.1-r4.zip](../../installers/ForestCryptQA-RadialQa-0.15.1-r4.zip).
Из 11 файлов полезной нагрузки относительно r3 изменён только `forest-manual-test.json`: точное имя
теперь `RadialQa`. Обновлены manifest и инструкция. Код установщика, DLL 0.15.1, баланс и подключение прежние.
На сервере обновлены такое же имя ручного теста и список `Players` серверного журнала.
Идентификатор `radial-r3-stand` сохранён: завершённая подготовка повторяться не должна.
Инвентарь будет заменён бронзовым комплектом только при первом успешном завершении этой подготовки;
`ResetPov=false`. Файлы персонажа вручную не редактировались, новый персонаж не создавался.

Пользователь подтвердил закрытие Valheim. При нулевом числе соединений запрошено сохранение,
получен checkpoint ServerManager с `pending=0`, сервер штатно остановлен и создана согласованная
копия 682 файлов savedir и конфигов с проверкой SHA256. Только затем применены настройки и выполнен запуск.
Серверный допуск читается при запуске сетевой сессии; простой замены JSON недостаточно.
Сервер 0.14.1 и Drug не менялись. CPU 150%, RAM 3 ГиБ и отсутствие таймера остановки сохранены.

## Проверки и пределы

- [Проверка конфигурации](../../scripts/check-forest-preparation.py) обнаружила обе ошибки старой поставки;
  кандидат и установленные серверные настройки прошли сверку с фактическим именем и 11 SHA256.
- Нативный `loadout-check` подтвердил 14 типов предметов в 18 стеках, включая бронзовое снаряжение качества 3.
  Комплекты клиента и сервера идентичны. Эта проверка создаёт данные предметов, но не выдаёт их персонажу.
- Закреплённый валидатор ServerManager разрешил девять модов с установленными эталонами.
  Ранее успешное подключение подтверждено пользователем; новая клиентская подготовка ещё не подтверждена.
- После перезапуска готовы Steam-порт, хранилище персонажей и серверный журнал `MANUAL_SERVER_READY`.
  Сохранились десять планов, данные 2331 помеченного объекта и SHA256 трёх файлов персонажей.
  Позиции подвижных объектов из сравнения исключены. Новые участки после первого входа не откатывались.
- Целостность ZIP и каждого файла payload проверена. Неизменный установщик ранее проверен в Windows;
  нового запуска Windows или игрового клиента агента для r4 не было.

Для повторного входа установить r4 в закрытую тестовую игру через `INSTALL.cmd`, выбрать существующего
RadialQa и кнопку `R3 / R4`. Инвентарь оставить закрытым до «Тест готов»: он блокирует перенос и выдачу,
а после окончания вступления срок подготовки ограничен 90 секундами.
Ожидаются каменный хаб, бронзовый комплект качества 3 и питание; god включён, ghost выключен.
Фактические прибытие и выдача ожидают пользователя. **R3/R4 открыты**, R2 не повторяется, U9 отложена.

## Восстановление

Приватные доказательства, кандидат, предыдущие сохранения и настройки находятся в
`.local/radial-stand-0151-r3/preparation-fix/` и `before-preparation-fix-checkpoint/` рядом с ним.
Новый checkpoint содержит свежий мир, персонажей и исправленные эталоны модов, но старый допуск подготовки:
при восстановлении поверх его config применить `forest-manual-test.json` и `forest-manual-server.json`
из `preparation-fix/candidate-config/`. Прежний `handoff-checkpoint` дополнительно требует overlay
`mod-policy-fix/candidate/` в ServerManager и не содержит прогресса первого пользовательского входа.
Не восстанавливать его поверх свежего прогресса для исправления конфигурации.
Backup клиента перед r4 возвращает r3; для возврата к 0.14.1 нужен backup перед исходной установкой r3.
[Состав, SHA256 и результаты](../../manifests/radial-stand-0151-r4-20261031.lock.json).

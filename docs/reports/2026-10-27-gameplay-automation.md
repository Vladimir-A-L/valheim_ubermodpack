# Автоматические игровые сценарии и подключение к серверу

Даты: 27–28 октября 2026 года, Asia/Yekaterinburg. В машинных артефактах используются UTC и QPC Windows.
Проверялся один Windows-клиент и отдельный Linux dedicated server на стенде разработки.
Это базовая игровая проверка кандидата, не полная приёмка модпака.

## Профиль и изоляция

- Сервер: Valheim `l-1.0.20`, Steam build `25909431`, протокол 41.
- Клиент: Steam build `25909357`, версия 1.0.20, протокол 41.
- Состав: исходный `core-candidate.lock.json`, теперь сохранённый в
  [истории](../../manifests/history/core-20261027.lock.json); обновлений игры или модов в этом прогоне не выполнялось.
  На клиенте сверены 16 DLL плагинов, загружены 13 плагинов. На сервере — 12 плагинов.
- Отдельная копия Windows-клиента, запуск с `-savedir`, новый персонаж `Automation`.
  Персонаж переведён из Cloud save в Local save через игровой интерфейс.
  Фактическое расположение файлов персонажа проверено при завершении; особенность описана ниже.
- Отдельная серверная поставка и новый мир `GameplayAutomation`; обычная добыча задана ×3.
- Клиент: 1280×720, DPI 96, английский интерфейс. Консольное окно BepInEx отключено в тестовой копии.
- Стенд: 6 vCPU и около 7,8 ГиБ RAM. Лимиты сервера: 200% CPU, сначала 4 ГиБ RAM, затем 5 ГиБ.
  Пик учтённой памяти первого прогона — 3 826 733 056 байт, около 3,56 ГиБ. Это не нагрузочный тест.

## Инструменты и подтверждённые проверки

Добавлены общий транспорт интерактивных заданий Windows, исполнитель SendInput, сценарный исполнитель
с Tesseract 5.5.0 и JSON-сценарии. Игровые клавиши отправляются физическими scan codes, текст — Unicode.
Кадры и журналы действий сохраняются до и после ввода; успешная отправка не считается игровым результатом.

| Проверка | Результат и способ подтверждения |
| --- | --- |
| Главное меню кандидата | Визуальная оценка кадра; видна версия игры, диалоги модов пройдены |
| Меню сохранений | Автоматически: три перехода, все предусловия и постусловия подтверждены OCR |
| Первый вход | Визуально: персонаж у стартовых камней и HUD; журналы подтверждают peer и протокол 41 |
| Игровое управление | Визуально: после 700 мс `W` персонаж повернулся и приблизился к камню |
| Инвентарь | Автоматически: закрытие, открытие и закрытие; OCR подтвердил `Craft` и `Meadows` |
| Устаревший кадр | `observation_expired`, `input_performed=false` на Windows |
| Повтор действия | Повторный `action_id` отклонён до ввода; ранее открытый инвентарь не переключён повторно |
| Свёрнутое окно | `window_not_visible`, `input_performed=false` |
| Перемещённое окно | `target_changed`, `input_performed=false`; следующий ввод только после нового наблюдения |
| Сохранение и выход | Визуально: индикатор сохранения и обновлённое время; затем подтверждён выход peer |
| Остановка сервера | Штатный SIGINT и завершённое `World save (5/5) done` |
| Backup/restore | Полный серверный runtime и состояние извлечены в новый каталог; SHA256 всех 1165 файлов совпали |
| Вход после восстановления | Подтверждён мир; три шага от поля пароля до игрового интерфейса прошли автоматически |
| Полный автоматический вход | После сбоя: все пять шагов от Favorite до `Meadows` прошли OCR-проверку |
| Инвентарь после восстановления | Визуально сохранились факел, туника и вес 3/300 |

При первом вводе текста обнаружена несовместимость сокращения `[ushort]` с Windows PowerShell 5.1;
оно заменено на `[uint16]`. Виртуальные коды клавиш работали в текстовых полях, но не открывали игровой
инвентарь; переход на scan codes подтверждён реальным нажатием `Tab` и автоматическим сценарием.

OCR имени персонажа не прошёл порог на декоративном шрифте: результат оставлен `inconclusive`,
правильное имя проверено визуально. При настройке области адреса сервера OCR также отказал до первого
действия. Порог уверенности не снижался; границы области уточнялись по кадру фиксированного профиля.
Для золотого заголовка пароля выделяется цвет текста; исходные кадры сохраняются.
Ранние попытки полного подключения не подтвердили переход после Connect и завершились без повторного клика.
Диагностическое нажатие `Enter` по новому кадру выбранного сервера открыло диалог пароля;
этот способ подтверждения добавлен в сценарий. Причина различия с кликом не установлена.

## Проверка после сбоя

После сообщения пользователя проверены процессы, задания Windows, журналы и исходный backup.
Журнал Linux содержит смену загрузок; время текущей загрузки при аудите — 27 октября, 23:54.
Серверный процесс отсутствовал, клиент показывал `Disconnected`; причина перезапуска стенда не установлена.
Финальная штатная остановка этого запуска не подтверждена. Последнее завершённое сохранение мира
записано в 23:44:31. Проверенный полный backup сохранил прежний SHA256.

Для продолжения создана ещё одна отдельная копия runtime и последнего состояния после остановки процесса.
Она загрузилась с прежними версиями и лимитами 5 ГиБ/200% CPU. Проверки кода после сбоя прошли:
20 unit-тестов, compileall, shellcheck и `git diff --check`.
Полный сценарий подключения с подтверждением через `Enter` завершился успешно 28 октября в 00:20:28.
Визуально также подтверждены персонаж, стартовые камни, HUD и сообщение о сохранении мира.
Повторный трёхшаговый сценарий инвентаря завершился успешно в 00:22:30.

## Завершение и сохранность данных

Клиент закрыт через Quit; отсутствие процесса подтверждено отдельно от последнего кадра.
Сервер остановлен штатно: завершённое `World save (5/5) done` записано в 00:26:23.
Создан новый полный backup runtime и состояния сервера, записан SHA256; `tar --compare` подтвердил
совпадение с остановленной поставкой. Исходный проверенный backup сохранён.
Заданий `ValheimVision-*` и тестовых игровых процессов не осталось.

При финальной проверке каталог, переданный клиенту через `-savedir`, оказался пустым.
Локальные `automation.fch` и `automation.fch.old` фактически находились в стандартном `characters_local`.
Поэтому один аргумент запуска не подтверждает изоляцию клиентского хранилища в этой версии.
После закрытия игры сделан полный снимок стандартного каталога сохранений, сверены SHA256 всех пяти файлов.
Только два созданных тестом файла персонажа перенесены в каталог тестового профиля и дополнительно скопированы
в backup; их хеши совпали. Остальные файлы стандартного каталога не изменялись.
Повторный запуск сценариев требует подготовки хранилища персонажа, а не только указания `-savedir`.

Исходные параметры реестра импортированы, параметры `Screenmanager` сверены с исходным экспортом.
Первый скрипт завершения встретил ошибку приведения типов при чтении свойств реестра;
повторная проверка через имена значений Registry API завершилась успешно.

## Ограничения

В первом клиентском сеансе нет записей `Exception` и `[Error`; сохраняются предупреждения о неоднозначных
prefab Jotunn и предупреждения Unity. На сервере остаются известные сообщения headless-шейдеров и размещения
локаций. Это не основание объявлять сборку стабильной.

A2S_INFO не ответил ни Windows-клиенту, ни локальному запросу, хотя реальное Steam-подключение состоялось.
Причина отсутствия A2S-ответа не установлена; таймаут не следует выдавать за доказанный сетевой блок.

Не проверены контролируемая добыча ×3, строительство Forever Build 2, сортировка, бой, прогрессия,
сохранность построек/сундуков/наград и игра двух клиентов. TidyChests ещё не входит в кандидат.
Сценарии рассчитаны на зафиксированные разрешение, язык и расположение интерфейса.

Сырые журналы, кадры, адреса, пароль, инвентаризации, сохранения и backup находятся только в `.local/`
и приватных каталогах Windows. Исходные наблюдения не переименованы в успешные проверки:
оценки модели и результаты OCR записаны отдельно.

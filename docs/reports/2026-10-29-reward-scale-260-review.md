# Разбор предложения: шкала наград до 260 и добавка арены

Дата: 29 октября 2026 года, Asia/Yekaterinburg.
Пользователь выбрал штатное усиление противников при совместной игре и подтвердил правила интервалов,
повторных групп, оранжевого лесного финала и тройной охраны арены. Последнее уточнение:
**6–9 объектов ядер суммарно на арене**, без влияния разброса на охрану, и один дополнительный обычный сундук.
Порог красного предмета поднят с 210 до 230; длина цикла остаётся 260. Вариант с 12 объектами отменён.

Это разбор плана следующего кандидата. Действующая поставка 0.8.0, её конфиг наград и сохранения не изменены.
Выполнен расчёт на существующей модели; игровая генерация с новым наполнением ещё не проверена.

## Интервалы и границы

В записи пользователя левый знак неравенства перевёрнут. Смысл принят как `нижняя граница < B ≤ верхняя`.
Отрицательный бюджет недопустим; B=0 сохраняет обычный лут и не даёт нашей бюджетной добавки.

| Бюджет первой итерации | Бюджетная добавка | Основная охрана обычной комнаты |
| --- | --- | --- |
| 0 < B ≤ 10 | 50 монет | 2–5 |
| 10 < B ≤ 20 | 100 монет | 3–5 |
| 20 < B ≤ 40 | Magic, синий | 3–5 |
| 40 < B ≤ 55 | Rare, жёлтый | 3–6 |
| 55 < B ≤ 110 | Epic, фиолетовый | 4–7 |
| 110 < B ≤ 160 | Legendary, зелёный/бирюзовый | 4–8 |
| 160 < B ≤ 230 | Mythic, оранжевый | 5–9 |
| 230 < B ≤ 260 | Ancient, красный | 5–10 |

Для награды следующей группы используется остаток бюджета. Для численности охраны — полный бюджет,
без сброса плотности в начале следующей итерации. Выше 260 основная охрана обычной комнаты остаётся 5–10.
Ресурсный минимум, ранние дополнительные охранники, утроение арены и редкая добавка считаются отдельно.

Пользователь подтвердил совместное смещение награды и численности: при 160 < B ≤ 230 основная охрана
составляет 5–9, при 230 < B ≤ 260 — 5–10. Предыдущее замечание о диапазоне 210 < B ≤ 230 снято;
отдельные пороги численности не требуются. Независимость от разброса ядер сохраняется.

На B=260 не нужно выдавать Ancient дважды из двух пересекающихся условий.
Одна полная шкала закрепляет группу из одного Ancient; остаток равен нулю и ничего не добавляет.
Положительный остаток выше 260 открывает следующую итерацию по прежнему правилу групп 1, 2, 3 и далее.
До предметного интервала остаток даёт 50 или 100 монет однократно на сундук, без умножения на размер группы.

| Бюджет | Бюджетная награда |
| --- | --- |
| 230 | 1 оранжевый |
| 230,001 | 1 красный |
| 260 | 1 красный |
| 270 | 1 красный + 50 монет |
| 280 | 1 красный + 100 монет |
| 280,001 | 1 красный + 2 синих |
| 490 | 1 красный + 2 оранжевых |
| 490,001 | 3 красных |
| 520 | 3 красных |
| 780 | 6 красных |

Это шкала исходного бюджета, а не накопление монет и вещей повторными открытиями или количеством убийств.
К бюджетным монетам и группам не применяется дополнительный множитель ресурсов ×3.

## Последствия для лесного профиля

Новые пороги не меняют сам B: веса, сочетания и формула k остаются прежними.
Для фиксированной последовательности десяти лесных свойств первые восемь ступеней сохраняют награды.

| Свойств | B | Действующая шкала | Предложенная шкала |
| --- | ---: | --- | --- |
| 7 | 50,16936 | 1 жёлтый | 1 жёлтый |
| 8 | 76,09312 | 1 фиолетовый | 1 фиолетовый |
| 9 | 123,62934 | 1 оранжевый | 1 зелёный |
| 10 | 187,49366 | 1 красный + 100 монет | 1 оранжевый |

Поздние цвета становятся последовательными: жёлтый → фиолетовый → зелёный → оранжевый.
При сохранении конечного бюджета 175–200 красный предмет нашей добавки в этом лесном профиле недостижим:
он начинается строго выше 230. Штатная случайная выдача установленных модов от этой гарантии независима.
Три бюджетных сундука арены суммарно дадут три оранжевых вместо трёх красных и 300 монет.

Снижение поздней награды до оранжевого и сохранение нынешней силы охраны подтверждены пользователем.
Не повышать силу охраны или её бюджет автоматически только ради возврата красного цвета.
Сдвиг порога меняет гарантированную бюджетную добавку; вероятность отдельного штатного броска EpicLoot
от этого не меняется. Сужение красного интервала само по себе не задаёт процент выпадения во всём данже.

При B≈187,49 обычный диапазон охраны меняется с 5–10 на 5–9. Для арены сохраняется утроение:
15–27 скелетов и ещё 1–3 призрака, то есть **16–30 врагов** вместо диапазона 16–33.
Точное число требует новой генерации по seed; наблюдавшиеся 21 враг не являются новым расчётным результатом.
Дополнительные ядра и обычный сундук сами по себе не должны добавлять ещё одну группу охраны.

## Дополнительное содержимое арены

- Общее число объектов ядер на арене — целое от 6 до 9 включительно. Это итоговый диапазон, не добавка к шести.
- Подтверждено: выбирать 6, 7, 8 или 9 равновероятно при генерации отдельным потоком случайных чисел
  по seed арены и сохранять результат в плане. Выбор числа ядер не должен сдвигать выбор числа, видов
  или свойств охраны. Повторный вход и перезапуск не перебрасывают количество.
- Для обычного подбора с ресурсами ×3 ожидается 18–27 предметов из этих объектов. Фактический итог необходимо
  проверить подбором; в число объектов множитель заранее не закладывается.
- Три бюджетных сундука сохраняются; добавляется **четвёртый, с обычной таблицей лесного сундука**.
  Он не получает нашу бюджетную добавку. Штатные правила EpicLoot и PoV для обычного сундука сохраняются;
  обычное содержимое не означает гарантированного отсутствия магических предметов.
- Ранние гарантированные ядра сохраняются. Добавка арены остаётся необязательным запасом ресурсов.
- Арена остаётся одной ресурсной комнатой в квоте 2–4; увеличение числа объектов не создаёт новую комнату.
- Для других типов данжей выбирать их штатный ресурс прогрессии отдельно. Уникальные квестовые предметы
  нельзя автоматически размножать или умножать на ×3 по аналогии с ядрами склепа.

Текущий адаптер привязывает бюджетную награду ко всем контейнерам комнаты. Простое увеличение `ChestCount`
с трёх до четырёх поэтому не выполняет запрос: нужен явный признак обычного сундука и исключение из `Bind`.
Для дополнительных 0–3 объектов и контейнера также нужны допустимые точки без перекрытия проходов.

## Что требуется при реализации

Новая таблица совместима с существующей интервальной моделью: длина цикла берётся из последнего порога.
Нужно обновить конфиг, проверки границ/повторных циклов и ожидаемые диапазоны охраны; внести различие
обычных и бюджетных сундуков в план, размещение и диагностику; задать независимый разброс 6–9 объектов ядер.

Ранее созданные сундуки сохраняют собственную копию правил, поэтому изменение общего конфига не мигрирует их,
включая ещё не открытые. Для сравнения нужен новый тестовый данж по согласованному порядку подготовки.
Повторный вход и перезапуск не должны возвращать забранные ядра или заново наполнять сундуки.

# Серверные персонажи и ручной тест

Профиль ForestCryptQA использует ServerManager 1.2.5 и собственный модуль 0.6.0.
Версии, зависимости и SHA256 закреплены в [lock](../manifests/forest-template-060-20261029.lock.json).
[Описание автора](https://thunderstore.io/c/valheim/p/sighsorry/ServerManager/1.2.5/)
предназначено для Valheim 1.0.20. ServerCharacters одновременно не устанавливать.
Crossplay выключен; используется Steam backend. Это отдельный тестовый мир, не постоянный игровой сервер.

## Где находится состояние

- `<savedir>/ServerManager/characters`: серверные `.fch`, по аккаунтам и именам персонажей.
- `<savedir>/ServerManager/ServerManager.yml`: серверные правила; корректные изменения подхватываются автоматически.
- `<savedir>/ServerManager/required` и `optional`: эталонные DLL разрешённых плагинов, не место их установки.
- `<savedir>/ForestManual/<world UID>`: серверный ID и журнал измерений/условных смертей.
- `BepInEx/config/ForestCryptQA/outbox`: клиентская очередь ещё не подтверждённых событий.

Все эти данные, журналы, аккаунты и приватные настройки находятся вне Git.
Локальный `.fch` у клиента остаётся кэшем и резервом. При `loadServerCharacterOnJoin: true`
сервер возвращает свою последнюю принятую копию; изменения в одиночной игре её не заменяют.
Это серверный приоритет загрузки, а не отсутствие файлов персонажа на клиенте.
Сохранение персонажей не делает бой серверным: HP и игровой ввод по-прежнему рассчитывает клиент.

## Первый перенос

Перед переключением закрыть клиент и обеспечить его backup установщиком. Сервер остановить штатно,
сохранить мир, внешние данные и прежнюю поставку. Для уже существующего персонажа на закрытом QA-сервере
на время первого входа поставить `loadServerCharacterOnJoin: false`. Допуск ограничить известными аккаунтами
через `permittedlist.txt`; идентификаторы не помещать в публичные конфиги.

После входа ServerManager принимает текущий профиль. Дождаться успешного сохранения мира и сообщения
`WorldCharacterCheckpointCompleted ... persisted=1, pending=0` либо большего числа сохранённых персонажей.
Одного сообщения о завершении сохранения мира недостаточно. Затем вернуть `loadServerCharacterOnJoin: true`
и проверить `ServerManager.yml settings reloaded.`. Смена действует на последующие подключения;
текущая сессия продолжает присылать обновления персонажа.

[finalize-character-import.py](../scripts/finalize-character-import.py) выполняет это одноразовое переключение:
ждёт конкретный непустой `.fch` и завершённый checkpoint, сохраняет исходную приватную копию,
атомарно меняет настройку и оставляет квитанцию. Передавать только пути отдельного закрытого стенда.
Не включать свободный импорт на открытом сервере. После переноса проверить повторный вход и состав вещей.
Квитанция подтверждает запись настройки; её применение проверяется по журналу ServerManager.

## Подготовка и счётчик

Клиентский модуль включается только для указанного имени в `ForestCryptQA`.
Он дожидается окончания вступления, земли и штатного cooldown телепортации; один раз переносит ко входу,
выдаёт согласованный комплект и начальное питание. Метки выдачи сохраняются в серверном профиле.
God включён, ghost выключен. При повторном входе комплект, телепортация и начальное лечение не повторяются.

Для новой кампании используется отдельный `PreparationId`. `ResetInventory=true` разрешён только
вместе с `AutoPrepareOnce=true` и новым ID; после backup он однократно заменяет инвентарь согласованным
комплектом. `forest-loadout.json` задаёт качество 3 для восьми предметов снаряжения; навыки и дерево PoV
не сбрасываются. Повторный вход с тем же ID сохраняет добычу и износ. `StartPosition` и `StartYaw` задают
проверенную наружную точку и направление; точка должна находиться вне триггера входного портала.
Подготовка ждёт готовности серверного счётчика. Новый ID нельзя менять ради обычного повторного входа.

Сервер принимает сообщения через RPC конкретного аутентифицированного соединения, проверяет имя,
порядок и уникальность событий. Клиент сообщает HP до/после урона; сервер определяет переход
с > 1 до ≤ 1, записывает событие с UTC и подтверждает итог. Удары при оставшемся 1 HP не добавляют смерть.
После регенерации новое падение до 1 снова учитывается. Автоматического лечения в ходе боя нет.
Повторная доставка после потери подтверждения не увеличивает итог. Серверный журнал восстанавливается при старте.

Сообщение «Тест готов» появляется после серверного подтверждения начала попытки. При ошибке учёта
прекратить игровой тест, проверить журнал и очередь; не считать незарегистрированный отрезок принятой проверкой.
Контрольные пробы имеют отдельный счётчик и отключены серверной политикой пользовательского теста.
Измерения доверены клиенту: этот механизм предназначен для оценки баланса, не для защиты от читов.

## Администрирование и откат

Не править `.fch` одновременно с игрой: принятая сервером копия в памяти может перезаписать внешнее изменение.
Для планового редактирования завершить сессии, запросить `save`, дождаться checkpoint с `pending=0`,
остановить сервер и сделать согласованный backup. Для штатного восстановления использовать также
команды ServerManager из документации закреплённой версии. Удалять созданные им lock-файлы не требуется.

Резервировать вместе весь `<savedir>` (включая мир, ServerManager и ForestManual), конфиги и клиентское состояние.
Хранить 4 предыдущих `.fch` и до 5 согласованных полных checkpoint. При откате возвращать соответствующие
бинарники и эталонные DLL в `required`; SHA256 плагинов клиента должен совпасть с разрешённой поставкой.
Не устанавливать новые версии автоматически при запуске.

AzuAntiCheat не установлен. Встроенные проверки ServerManager переведены в `log`; режим `off` не поддерживается.
Пределы характеристик для QA подняты, но проверка состава модов и некоторые ограничения команд сохраняются.
Даже при `log` чрезмерный урон выше настроенного предела может блокироваться. Это нужно учитывать при будущем балансе.
DungeonMaps 1.1.2 находится в `optional` как клиентский мод; на dedicated server его устанавливать не нужно.
SHA256 клиентской DLL сверяется с эталоном. `BepInEx/config/DungeonMaps/` с историей исследования входит
в стандартный клиентский backup конфигов. Для новой квоты нужен новый склеп: существующие комнаты не перестраиваются.
Discord-интеграция не настроена. Клиентский логотип и быстрый вход по умолчанию отключены нашим конфигом.
